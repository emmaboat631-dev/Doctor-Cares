6 · Design notes for Phase 1

Direction for the polished UI once wireframes are approved.
Color

Calm healthcare palette: soft white surface, deep-blue primary (~ #1E5EFF), muted teal secondary, warm neutrals. Semantic: success #16A34A, warning #F59E0B, danger #DC2626. Dark mode = deep slate surface with reduced blue saturation.

Typography

Single sans-serif family (Inter). Sizes: 12 / 14 / 16 / 18 / 20 / 24 / 30. Line-heights 1.4–1.5. Numeric weights: 400 / 500 / 600 / 700.

Spacing & radius

4px base grid. Cards: radius 12–16px, subtle shadow (0 1px 2px rgba(0,0,0,.06)). Buttons: 44px min touch target on mobile.

Navigation

Mobile: fixed bottom nav (5 items, role-dependent). Tablet ≥ 768px: same but wider. Desktop ≥ 1024px: left sidebar for Doctor + Admin, top nav for Patient marketing pages.

Component library

Own components (Button, Input, Card, DoctorCard, AppointmentCard, MessageBubble, EmptyState, LoadingSpinner, ErrorState, BottomNavigation, Sidebar, Header, NotificationItem). Icons from lucide-react.

Accessibility

Semantic HTML, labels for all fields, visible focus ring on interactive elements, prefers-reduced-motion respected, minimum 4.5:1 text contrast in both themes.

Data & auth

All data comes from Supabase (Postgres + RLS + Realtime + Storage). No hardcoded lists. Frontend never uses the service-role key. OpenFDA fetched directly from the browser (no key required).

Screen count reconciliation

47 required screens are covered by these wireframes as combined flows (e.g. Find doctors + filter = one flow, Professional profile view + edit share layout). Explicit numbers on each frame map to the spec.
